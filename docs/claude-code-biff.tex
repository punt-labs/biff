% ============================================================
\section{Introduction}
% ============================================================

This specification extends the base Claude Code state machine
(\texttt{claude-code.tex}) with biff communication and workflow
coordination state. Biff provides team communication primitives
modeled after BSD Unix tools: \texttt{/plan}, \texttt{/who},
\texttt{/finger}, \texttt{/write}, \texttt{/read}, \texttt{/wall},
and \texttt{/talk}.

The key workflow invariants enforced by this model:

\begin{enumerate}
  \item \textbf{Plan before editing}: Claude must set a plan (via
    \texttt{/plan} or auto-detect from git branch) before editing
    files. The \texttt{PreToolUse} hook matches \texttt{Edit|Write}
    only; \texttt{Bash} is not gated.
  \item \textbf{Message awareness}: unread messages are surfaced
    before Claude declares ``done'' (Stop hook).
  \item \textbf{Wall awareness}: active wall broadcasts are injected
    into session context at startup.
\end{enumerate}

The gate depends on the plan alone. Biff is a communication tool and
does not depend on beads or \texttt{bd}: bead tracking is an orthogonal
concern the workflow gate never consults.

\section{Biff Types}

\begin{zed}
  [USERID, MSGID, WALLTEXT]
\end{zed}

\texttt{USERID} identifies a team member. \texttt{MSGID} uniquely
identifies a message. \texttt{WALLTEXT} is the content of a wall
broadcast.

\begin{zed}
  PlanSource ::= psManual | psAuto
\end{zed}

How the plan was set. \texttt{psManual} is an explicit \texttt{/plan}
command; \texttt{psAuto} is derived from the git branch name by the
\texttt{PostToolUse} Bash hook. A manual plan blocks auto-overwrite.

\begin{zed}
  ToolCategory ::= tcEdit | tcBash | tcOther
\end{zed}

Coarse tool classification for workflow gates. \texttt{tcEdit} covers
\texttt{Edit}, \texttt{Write}, and similar file-modifying tools.
\texttt{tcBash} covers shell commands. \texttt{tcOther} is everything
else (read-only tools, MCP queries, etc.).

\section{State}
% ============================================================

The state combines the base Claude Code state with biff workflow
state in a single flat schema. Base invariants are preserved and
biff invariants are added.

\begin{schema}{State}
  %
  % --- Base Claude Code state ---
  %
  sessionId : \finset SESSIONID \\
  sessionPhase : SessionPhase \\
  permMode : PermissionMode \\
  toolPhase : ToolPhase \\
  currentTool : \finset TOOLNAME \\
  toolCategory : ToolCategory \\
  toolsThisTurn : \nat \\
  activeSubagents : \finset AGENTID \\
  context : \seq CONTEXTCHUNK \\
  pendingPrompt : \finset PROMPT \\
  pendingResponse : \finset RESPONSE \\
  %
  % --- Biff workflow state ---
  %
  planSet : AGENTID \pfun ZBOOL \\
  planSource : AGENTID \pfun PlanSource \\
  planWiped : ZBOOL \\
  unreadCount : \nat \\
  talkActive : ZBOOL \\
  wallActive : ZBOOL \\
  wallText : \finset WALLTEXT
  \where
  %
  % === Base invariants (from claude-code.tex) ===
  %
  \# sessionId \leq 1 \\
  %
  % A session id exists exactly during the strictly-active phases.  The
  % original statement (``sessionPhase \neq spInactive \implies \#
  % sessionId = 1'') wrongly demanded a session id at $spEnded$ too,
  % directly contradicting EndSession's own postcondition (sessionId' =
  % \emptyset there) --- an unsatisfiable conjunction that made EndSession
  % unfireable in ProB (no successor state could ever satisfy both).
  % Errata, corrected here: $spEnded$ joins $spInactive$ as a phase with
  % no session id, matching the precedent already set for
  % $activeSubagents$/$pendingPrompt$ two lines below, both of which
  % already exempt $spEnded$ the same way.
  %
  sessionPhase \in \{ spInactive, spEnded \} \implies sessionId = \emptyset \\
  sessionPhase \notin \{ spInactive, spEnded \} \implies \# sessionId = 1 \\
  sessionPhase \neq spProcessing \implies toolPhase = tpNone \\
  \# currentTool \leq 1 \\
  toolPhase = tpNone \implies currentTool = \emptyset \\
  toolPhase \neq tpNone \implies \# currentTool = 1 \\
  toolsThisTurn \leq maxTools \\
  sessionPhase = spInactive \implies activeSubagents = \emptyset \\
  sessionPhase = spEnded \implies activeSubagents = \emptyset \\
  \# activeSubagents \leq maxSubagents \\
  \# context \leq maxContext \\
  \# pendingPrompt \leq 1 \\
  sessionPhase = spIdle \implies pendingPrompt = \emptyset \\
  sessionPhase = spInactive \implies pendingPrompt = \emptyset \\
  sessionPhase = spEnded \implies pendingPrompt = \emptyset \\
  \# pendingResponse \leq 1 \\
  sessionPhase \neq spResponding \implies pendingResponse = \emptyset \\
  %
  % === Tool category tracks current tool ===
  %
  toolPhase = tpNone \implies toolCategory = tcOther \\
  %
  % === Biff invariants ===
  %
  % Plan source exists iff plan is set, stated per identity now that
  % planSet/planSource are indexed rather than session-global (biff-ar1/om9,
  % \S\ref{sec:om9}).  The old cardinality-based encoding (a finset of size
  % $\leq 1$ standing for ``optional'') is replaced by the more direct
  % optional-via-partial-function idiom, since the key already distinguishes
  % identities.
  %
  \dom planSource \subseteq \dom planSet \\
  \forall a : \dom planSet @ ( planSet(a) = ztrue \iff a \in \dom planSource ) \\
  %
  % Bounded for animation --- ProB will not animate an unbounded carrier,
  % and the domain of planSet is exactly the population of identities the
  % model has ever seen ask about or set a plan: the current session plus
  % at most maxSubagents concurrently observed peers.
  %
  \#(\dom planSet) \leq maxSubagents + 1 \\
  %
  % Unread bounded for animation
  %
  unreadCount \leq maxUnread \\
  %
  % Wall text exists iff wall is active
  %
  \# wallText \leq 1 \\
  wallActive = zfalse \implies wallText = \emptyset \\
  wallActive = ztrue \implies \# wallText = 1 \\
  %
  % No biff state when session is inactive --- except planSet/planSource,
  % which (\S\ref{sec:om9}) now persist across this session's own lifecycle
  % boundary by design: they model the shared, identity-indexed marker file
  % on disk, not this session's local memory, so another identity's entry
  % must survive this session going inactive.  Dropping the old
  % ``sessionPhase = spInactive \implies planSet = zfalse'' invariant is
  % deliberate, not an oversight --- see \S\ref{sec:om9}.
  %
  sessionPhase = spInactive \implies unreadCount = 0 \\
  sessionPhase = spInactive \implies talkActive = zfalse \\
  sessionPhase = spInactive \implies wallActive = zfalse
  %
  % om9 regression guard (\S\ref{sec:om9}): $planWiped$ is deliberately
  % NOT pinned here (errata --- an earlier draft of this schema did pin
  % it, on the mistaken reasoning that this file's absence of
  % deadlock/liveness analysis made nats-relay.tex's warning about
  % pinned ghost observers inapplicable). It is not: declaring a ghost
  % as part of \texttt{State}'s own invariant makes ProB treat it as a
  % WELL-FORMEDNESS FILTER on successor states --- any transition whose
  % postcondition would set it to $ztrue$ is silently excluded from the
  % reachable graph rather than reported, so ordinary \texttt{-model\_check}
  % can never find the very counterexample the ghost exists to surface
  % (confirmed empirically: pinning it collapses an 8-state reachable
  % counterexample trace down to 4 states, none of them a violation).
  % The correct idiom, matching \texttt{nats-relay.tex}'s
  % $spuriousTeardown$ exactly, is a free ghost variable checked by an
  % explicit CTL formula: \texttt{probcli claude-code-biff.tex
  % -ctlformula "AG({planWiped = zfalse})"}.
\end{schema}

\subsection{Identity-Indexed Plan State --- the biff-ar1 / biff-om9 Fix}
\label{sec:om9}

% DES-0XX PLACEHOLDER: the parallel code-implementation mission
% (m-2026-08-09-021, worker rmh, same design mission m-2026-08-09-018)
% logs this decision in DESIGN.md under its own DES-0XX entry number.
% As of this spec's authorship that entry had not yet landed on this
% branch (checked via `bd show biff-ar1`, which records no DES-0XX
% reference).  Fill in the real number here once rmh's mission closes
% and the entry exists --- do not guess it.

Earlier revisions of this specification modelled \texttt{planSet} as a
single flat \texttt{ZBOOL}: ``is the plan set,'' with no notion of
\emph{whose} plan.  That was adequate for a model of one session's own
perspective, but it could not even state, let alone rule out, the failure
mode reported as biff-ar1/biff-om9: two sessions (or an in-process
subagent and its leader, \texttt{claude-code.tex}'s $AGENTID$) sharing one
worktree, where one session's \texttt{SessionStart} unconditionally wiped
the shared on-disk marker file and so cleared a plan another, concurrently
running session depended on.  A flat boolean has no room for a second
occupant; the bug was invisible to the model, not merely unproven.

The fix (design mission \texttt{m-2026-08-09-018},
\texttt{.tmp/plan-gate-design/biff-ar1-om9-design.md} \S6) re-indexes
\texttt{planSet} and \texttt{planSource} by $AGENTID$ --- the same base
type \texttt{activeSubagents} already uses for ``the other identities this
session knows about,'' so this is filling a gap in the model's existing
vocabulary, not inventing a new one.  \texttt{StartSession} (and,
symmetrically, \texttt{EndSession}) must now update \emph{only its own}
key via functional override ($\oplus$), never the whole function.  The
ghost observer \texttt{planWiped} is the machine-checked statement of that
requirement: it starts \texttt{zfalse}, and the shipped
\texttt{StartSession} below is provably incapable of setting it, because
$(\, f \oplus \{x \mapsto v\}\,)(y) = f(y)$ for every $y \neq x$ is a
toolkit fact about override, not something that needs a search to confirm.
What \emph{does} need a search to confirm is that a naive, type-blind port
of the old assignment --- literally generalising
``\texttt{planSet}${}'{} = zfalse$'' to ``\texttt{planSet}${}'{} =
\emptyset$'' without rethinking the logic, exactly the kind of edit a
mechanical type-widening pass produces --- reintroduces the bug.

\texttt{planWiped} is deliberately \emph{not} pinned as a state invariant
here (errata --- an earlier draft of this schema pinned it, on the
mistaken belief that this file's lack of deadlock/liveness analysis made
\texttt{nats-relay.tex}'s warning about pinned ghost observers
inapplicable; it is not: pinning a ghost inside \texttt{State}'s own
invariant makes ProB filter violating successors out of the reachable
graph instead of reporting them, so ordinary model checking can never
find the very counterexample the ghost exists to surface).  The correct
idiom, matching \texttt{nats-relay.tex}'s $spuriousTeardown$ exactly, is
a free ghost variable checked by an explicit CTL formula:
\texttt{probcli claude-code-biff.tex -ctlformula "AG(\{planWiped =
zfalse\})"}.

This file's own state space (11 given types, 26 operations spanning the
whole base Claude Code tool-call lifecycle) is too large for probcli to
close exhaustively within a practical time budget --- confirmed
empirically, both plain \texttt{-model\_check} and the CTL check exceeded
280 seconds against the full spec, past 300,000 discovered states and
still climbing.  The counterexample and its closure are instead verified
against \texttt{claude-code-biff-om9-globalwipe.tex}, the formal
\emph{projection} of this spec onto exactly the five variables the om9
property depends on ($sessionPhase$, $sessionId$, $planSet$,
$planSource$, $planWiped$) --- every operation kept there
(\texttt{StartSession}, \texttt{SetPlanManual}, \texttt{EndSession}, and
the two phase-transition steps between them) reproduces the corresponding
shipped guard and postcondition verbatim, with only the erased fields'
frame conditions removed.  Against the pre-fix (naive global-wipe)
variant of that harness, \texttt{probcli -ctlformula "AG(\{planWiped =
zfalse\})"} reports the formula \textbf{FALSE} with an 8-step reachable
counterexample: register two identities' plans (\texttt{SetPlanManual}
for $A$, then $B$), end $A$'s own session (correctly clearing only $A$'s
key), then let $A$'s \emph{next} session start and wipe \emph{everything}
--- including $B$'s still-set plan.  That counterexample \emph{is}
biff-om9.  Against the fixed (override-based) variant of the identical
harness --- the same construction shipped in this file's own
\texttt{StartSession} below --- the same formula is \textbf{TRUE},
proven exhaustively over the harness's whole reachable state space (9
states) in under 30ms: the fix makes the bad state \emph{unreachable},
not merely less likely.

\subsection{StartSession}

\texttt{SessionStart} hook fires. Biff's \texttt{session-start.sh}
initializes the session. If a wall is active, it is injected into
context.

Errata (\S\ref{sec:om9}): the precondition was, in every prior revision
of this specification, \texttt{sessionPhase = spInactive} alone. That
made $spEnded$ a true dead end --- no operation in this file is ever
enabled from $spEnded$, so once one session's lifecycle finished, no
\emph{second} session could ever start within the same reachable-state
trace, and every multi-identity scenario this section exists to model
(including the om9 counterexample itself) was consequently unreachable
from \texttt{Init} for a reason having nothing to do with whether the
fix below is correct. The corrected precondition,
\texttt{sessionPhase = spInactive $\lor$ sessionPhase = spEnded},
allows a new session to start either as the very first one (from
\texttt{Init}) or as a successor to one that has already ended ---
exactly the ordinary case of a second Claude Code session starting in
the same worktree later, which is the scenario biff-om9 is about.

$identity?$ is the resolved plan-marker identity for the starting
session --- \emph{not} necessarily the same token as $sid?$
(\S\ref{sec:om9}: the code resolves $session\_id$ or $agent\_id$
depending on how the session was dispatched, per design \S3a).  They are
modelled as separate inputs of separate given types precisely because
the code resolves them from separate fields on the hook payload, and
conflating them would hide the exact identity-resolution ambiguity the
design document leaves open (OPEN-DECISION-1).  A new session inherits
no plan of its own --- the ``new session starts unset'' invariant biff's
\texttt{clear\_plan\_marker} call encodes --- but, critically, it must
touch \emph{only} $identity?$'s own entry in $planSet$/$planSource$,
never anyone else's: this is the formal statement of the biff-om9 fix.
Functional override ($\oplus$) makes that guarantee by construction,
since $(f \oplus \{x \mapsto v\})(y) = f(y)$ for every $y \neq x$.

\begin{schema}{StartSession}
  \Delta State \\
  sid? : SESSIONID \\
  identity? : AGENTID \\
  source? : SessionStartSource \\
  mode? : PermissionMode \\
  hasWall? : ZBOOL \\
  wallContent? : \finset WALLTEXT
  \where
  sessionPhase = spInactive \lor sessionPhase = spEnded \\
  \# wallContent? \leq 1 \\
  hasWall? = zfalse \implies wallContent? = \emptyset \\
  hasWall? = ztrue \implies \# wallContent? = 1 \\
  %
  sessionPhase' = spIdle \\
  sessionId' = \{ sid? \} \\
  permMode' = mode? \\
  toolPhase' = tpNone \\
  currentTool' = \emptyset \\
  toolCategory' = tcOther \\
  toolsThisTurn' = 0 \\
  activeSubagents' = \emptyset \\
  context' = \langle \rangle \\
  pendingPrompt' = \emptyset \\
  pendingResponse' = \emptyset \\
  %
  % THE FIX (\S\ref{sec:om9}): scope to identity?'s own key only, via
  % override --- every other identity's entry in planSet/planSource is
  % provably untouched.
  %
  planSet' = planSet \oplus \{ identity? \mapsto zfalse \} \\
  planSource' = \{ identity? \} \ndres planSource \\
  %
  % Regression guard: planWiped can only ever be driven to ztrue by an
  % operation whose postcondition actually clears another identity's
  % ztrue entry.  Under the override above that never happens, so this
  % disjunction's second disjunct is the only one ever reachable here ---
  % but it is stated as a disjunction, not assumed, so a future edit to
  % the postcondition above that reintroduces global clearing is caught
  % by z-spec test, not merely by inspection.
  %
  ( ( \exists a : \dom planSet @
        a \neq identity? \land planSet(a) = ztrue \land
        ( a \notin \dom planSet' \lor planSet'(a) = zfalse ) )
    \land planWiped' = ztrue ) \\
  \lor \\
  ( ( \lnot ( \exists a : \dom planSet @
        a \neq identity? \land planSet(a) = ztrue \land
        ( a \notin \dom planSet' \lor planSet'(a) = zfalse ) ) )
    \land planWiped' = planWiped ) \\
  %
  unreadCount' = 0 \\
  talkActive' = zfalse \\
  wallActive' = hasWall? \\
  wallText' = wallContent?
\end{schema}

\subsection{PreToolHookAllow --- with workflow gate}

The \texttt{PreToolUse} hook checks workflow prerequisites for
edit tools (the shipped hook matches \texttt{Edit|Write} only). The
hook allows only if the plan is set (for edit tools), or
unconditionally for other tools --- including \texttt{Bash}, which
is not gated. $identity?$ (\S\ref{sec:om9}) is the identity the hook
resolves for \emph{this} invocation --- $session\_id$ from the hook's
own JSON payload, or $agent\_id$ when present for an in-process
subagent's own tool call (design \S3a) --- and the guard now checks
\emph{that} identity's own entry in $planSet$, not a flat, session-global
boolean: two identities sharing one worktree can have independently true
or false plans.

\begin{schema}{PreToolHookAllow}
  BiffFrame \\
  hookDecision? : PermissionDecision \\
  needsPermission? : ZBOOL \\
  identity? : AGENTID
  \where
  sessionPhase = spProcessing \\
  toolPhase = tpPreHook \\
  hookDecision? = pdAllow \\
  %
  % WORKFLOW GATE (biff-ar1/om9 fix, \S\ref{sec:om9}): edit tools require
  % identity?'s OWN plan to be set (Bash is not gated).  Written total ---
  % an identity absent from dom planSet has no recorded plan, and the
  % guard correctly denies rather than leaving planSet(identity?)
  % undefined.
  %
  toolCategory = tcEdit \implies
    identity? \in \dom planSet \land planSet(identity?) = ztrue \\
  %
  toolPhase' = \IF needsPermission? = ztrue \THEN tpPermission \ELSE tpExecuting \\
  %
  sessionPhase' = sessionPhase \\
  sessionId' = sessionId \\
  permMode' = permMode \\
  currentTool' = currentTool \\
  toolCategory' = toolCategory \\
  toolsThisTurn' = toolsThisTurn \\
  activeSubagents' = activeSubagents \\
  context' = context \\
  pendingPrompt' = pendingPrompt \\
  pendingResponse' = pendingResponse
\end{schema}

\subsection{PreToolHookDeny}

The hook denies the tool call (workflow prerequisites not met,
or explicit deny for other reasons). $identity?$ is carried here too
(\S\ref{sec:om9}, design \S6) --- the hook resolves the calling identity
once, before branching to allow or deny, so every \texttt{PreToolUse}
invocation, allowed or denied, is associated with the same identity
token.  \texttt{PreToolHookDeny} is deliberately the general ``deny''
outcome (workflow gate \emph{or} any other reason the hook chooses to
deny), so unlike \texttt{PreToolHookAllow} it does not itself constrain
$planSet(identity?)$ --- $identity?$ documents whose call was denied,
which is exactly the field a denial audit trail would need.

  toolCategory' = tcOther \\

  sessionId' = sessionId \\
  permMode' = permMode \\

\section{System Invariants}
% ============================================================

The specification enforces these properties across all reachable states:

\begin{enumerate}
  \item \textbf{Plan before editing} (workflow gate): the
    \texttt{PreToolHookAllow} operation requires
    \texttt{identity? $\in$ dom planSet $\land$ planSet(identity?) =
    ztrue} for edit tools (\texttt{tcEdit}) --- \emph{that specific
    identity's own} plan, not a session-global flag
    (\S\ref{sec:om9}). No path through the state machine can reach
    tool execution for file-modifying tools without \emph{that
    identity} having a set plan. \texttt{Bash} is not gated (the
    shipped hook matches \texttt{Edit|Write} only). The gate consults
    the plan alone --- never beads.

  \item \textbf{Manual plan blocks auto}: \texttt{SetPlanAuto} has
    precondition \texttt{identity? $\notin$ dom planSource $\lor$
    planSource(identity?) $\neq$ psManual}, preventing auto-detection
    from overwriting an explicit plan --- checked against
    \texttt{identity?}'s own source entry.

  \item \textbf{Wall consistency}: wall text exists if and only if
    the wall is active. No orphan text, no active wall without content.

  \item \textbf{Plan consistency}: plan source exists if and only if
    plan is set, for every identity independently:
    \texttt{$\forall a : \dom\ planSet @ ( planSet(a) = ztrue
    \iff a \in \dom\ planSource )$}.

  \item \textbf{No cross-identity interference} (biff-ar1/om9 fix,
    \S\ref{sec:om9}): \texttt{planWiped = zfalse} holds across every
    reachable state. \texttt{StartSession}, \texttt{EndSession},
    \texttt{SetPlanManual}, \texttt{SetPlanAuto}, and
    \texttt{StartSubagent} update $planSet$/$planSource$ only via
    functional override or domain subtraction on their \emph{own}
    identity key, so no operation can ever clear another identity's
    already-set plan. The frozen artifact
    \texttt{claude-code-biff-om9-globalwipe.tex} demonstrates the
    converse: a \texttt{StartSession} that naively assigns
    \texttt{planSet}${}'{} = \emptyset$ (the type-blind generalisation
    of the old flat \texttt{planSet}${}'{} = zfalse$) makes
    \texttt{planWiped = zfalse} false, and probcli returns the
    counterexample --- that counterexample \emph{is} biff-om9.

  \item \textbf{Clean session boundaries}: all biff state --- except
    \emph{other identities'} $planSet$/$planSource$ entries, which are
    deliberately persistent (\S\ref{sec:om9}) --- is cleared on
    \texttt{Init} and, for its own identity, on \texttt{EndSession}. No
    session's own state leaks into a session that starts after it.

  \item \textbf{Talk exclusivity}: \texttt{StartTalk} requires
    \texttt{talkActive = zfalse}; \texttt{EndTalk} requires
    \texttt{talkActive = ztrue}. No double-start or double-end.

  \item \textbf{All base invariants preserved}: tool phase, session
    phase, subagent, and context invariants from the base model hold.
\end{enumerate}

\section{Use Case Integration Validation}

This section cross-references each use case from
\texttt{biff\_coordination\_use\_cases\_v0.2.md} against the Z
specification operations and state variables. For each use case,
we identify: (1) which Z operations model the behavior, (2) what

\subsection{Group A: Presence}
% ------------------------------------------------------------

\subsubsection{UC1 --- Check Who's Working on What}

\textbf{Z coverage:} Not modeled as an operation. \texttt{/who} is a
read-only query that does not change state. However, the state it reads
(\texttt{planSet}, \texttt{planSource}, \texttt{talkActive}) is maintained
by the model, now per identity (\S\ref{sec:om9}): a \texttt{/who} query
sees each identity's own plan, not one session-global flag.

\textbf{What the model proves:} The \texttt{planSet} and
\texttt{planSource} variables are always consistent (invariant 4:
plan source exists iff plan is set, per identity) and no identity's
entry can be disturbed by another identity's session lifecycle
(invariant 5, the biff-ar1/om9 fix). Any \texttt{/who} query will
see coherent plan state for every identity --- never a dangling
source without a plan, a plan without a source, or one identity's
plan clobbered by another's \texttt{SessionStart}.

\textbf{Gap:} None for V1. The idle time display relies on
\texttt{last\_active} timestamps in the relay, which is outside the
model's scope (relay internals are opaque).

\subsubsection{UC2 --- Inspect a Teammate's Availability}

\textbf{Z coverage:} Not modeled as an operation. Same rationale as UC1
--- read-only query. The \texttt{talkActive} state is accurate because
\texttt{StartTalk} and \texttt{EndTalk} enforce exclusivity (invariant 7).

\textbf{What the model proves:} A \texttt{/finger} query will never show
a session simultaneously in talk and not-in-talk. The talk state is
consistent across all reachable states.

\textbf{Gap:} None. The \texttt{mesgMode} (DND) variable was proposed
but not included in this model. If DND status needs formal verification,
add \texttt{mesgMode : ZBOOL} to the state schema.

\subsubsection{UC3 --- Declare What You're Working On}

\textbf{Z coverage:} Fully modeled.

\begin{itemize}
  \item Manual path: \texttt{SetPlanManual} --- sets
    \texttt{planSet(identity?) = ztrue},
    \texttt{planSource(identity?) = psManual}.
  \item Auto path: \texttt{SetPlanAuto} --- sets
    \texttt{planSet(identity?) = ztrue},
    \texttt{planSource(identity?) = psAuto}, guarded by
    \texttt{identity? $\notin$ dom planSource $\lor$
    planSource(identity?) $\neq$ psManual}.
  \item \texttt{/tty} naming is outside the model (relay metadata, no
    workflow impact).
\end{itemize}

\textbf{What the model proves:}

\begin{enumerate}
  \item \textbf{Manual blocks auto}: \texttt{SetPlanAuto} has
    precondition \texttt{identity? $\notin$ dom planSource $\lor$
    planSource(identity?) $\neq$ psManual}, checked per identity. The
    model checker verifies that no auto-plan overwrites a manual plan
    for that identity, and (\S\ref{sec:om9}) that it cannot touch any
    \emph{other} identity's plan either --- see the model-check report
    for the current state count.
  \item \textbf{Plan is prerequisite for editing}: Once the
    plan-before-editing gate is active, the model proves that no file
    edit (\texttt{tcEdit}) executes for identity $a$ without
    \texttt{planSet(a) = ztrue} (\texttt{Bash} is not gated). This
    validates the use case's claim that plan declaration is
    meaningful --- it is enforced, not advisory, and (\S\ref{sec:om9})
    it is enforced \emph{per identity}: one agent's plan does not
    authorise another's edits.
\end{enumerate}

\textbf{Gap:} Bead ID expansion (step 3 in the use case) is a relay-side
detail, not modeled.

% ------------------------------------------------------------
\subsection{Group B: Asynchronous Messaging}
% ------------------------------------------------------------

\subsubsection{UC4 --- Send a Focused Message}

\textbf{Z coverage:} Partially modeled. The send action is a tool
completion side effect (noted in the Hook Event Map as
\texttt{PostToolUse} on \texttt{biff\_\_write}). The model does not
track outbound messages because they do not affect the sender's
workflow state.

\textbf{What the model proves:} Sending a message does not disrupt
any workflow invariant. The \texttt{BiffFrame} ensures all biff state
is preserved through tool completions. No state corruption from
interleaving \texttt{/write} with other operations.

\textbf{Gap:} Recipient-side effects (unread count increment, push
notification) are modeled by \texttt{ReceiveMessage}, but the causal
link between send and receive is not captured --- they are independent
events in the model, which matches reality (async, fire-and-forget).

\subsubsection{UC5 --- Check and Process Incoming Messages}

\textbf{Z coverage:} Fully modeled.

\begin{itemize}
  \item \texttt{ReceiveMessage} --- increments \texttt{unreadCount} when
    a message arrives (external event, can fire in any active session phase).
  \item \texttt{ReadMessages} --- resets \texttt{unreadCount} to 0 when
    the agent calls \texttt{/read}.
\end{itemize}

\textbf{What the model proves:}

\begin{enumerate}
  \item \texttt{unreadCount} is bounded (\texttt{$\leq$ maxUnread}), so
    the model is finite and fully explorable.
  \item \texttt{ReceiveMessage} can fire during any session phase
    (idle, processing, responding) except \texttt{spInactive} and
    \texttt{spEnded}. This correctly models NATS push notifications
    arriving asynchronously.
  \item \texttt{ReadMessages} requires \texttt{spProcessing} and
    \texttt{toolPhase = tpNone}, which correctly reflects that \texttt{/read}
    is a tool call during the agentic loop.
\end{enumerate}

\textbf{Gap:} POP semantics (messages consumed once, then deleted) are
not modeled --- the count goes to 0, but we do not track individual
message identity. Sufficient for workflow invariants.

\subsubsection{UC7 --- Escalate a Decision to a Human}

\textbf{Z coverage:} Not modeled as a distinct operation. The use case
document proposes a \texttt{Stop} hook that injects escalation guidance.
In the Z spec, the \texttt{FinishResponse} operation's \texttt{Stop}
hook is the attachment point.

\textbf{What the model proves:} The \texttt{Stop} hook fires on every
\texttt{FinishResponse} (operation 15) and \texttt{ForceContinue}
(operation 16). There is no path to \texttt{spIdle} from
\texttt{spResponding} that bypasses the Stop hook. If a Stop hook
injects escalation guidance, the agent will see it.

\textbf{Gap:} The model does not track \emph{whether} the agent actually
escalated. This would require a new state variable
(\texttt{escalationPending : ZBOOL}) set when the agent identifies an
unresolved decision and cleared when it sends \texttt{/write}. Worth
adding if escalation compliance becomes a hard requirement.

\textbf{Proposed extension:}

\begin{verbatim}
  escalationPending : ZBOOL
  ...
  % In FinishResponse:
  escalationPending = ztrue ==> hookResult? = hdBlock
\end{verbatim}

This would make escalation a hard gate: the agent cannot stop until it
has sent the escalation message.

\subsubsection{UC8 --- Report Task Completion}

\textbf{Z coverage:} Partially modeled. The \texttt{PostToolUse} hook
on PR creation (existing \texttt{pr-announce.sh}) fires after
\texttt{CompleteToolSuccess}. The \texttt{Stop} hook at session end
maps to \texttt{FinishResponse}.

\textbf{What the model proves:} \texttt{CompleteToolSuccess} always
fires after successful tool execution, and the PostToolUse hook fires
as a side effect. There is no path where a PR is created but the
PostToolUse hook is skipped.

\textbf{Gap:} The model does not track whether a PR was created during
the session (\texttt{prCreated : ZBOOL}). Without this, the Stop hook
cannot conditionally remind about announcement. Worth adding for the
session close protocol validation.

\subsubsection{UC9 --- Redirect an Agent's Priorities}

\textbf{Z coverage:} Modeled via \texttt{ReceiveMessage}.

\textbf{What the model proves:} A message can arrive at any time during
an active session (\texttt{ReceiveMessage} fires in \texttt{spIdle},
\texttt{spProcessing}, or \texttt{spResponding}). The agent will
eventually see the redirect --- either via push notification (tool
description mutation, outside the model) or on its next \texttt{/read}.

\textbf{Gap:} The model does not capture the agent's response to
redirection (changing plan, switching tasks). This is behavioral, not
state-machine-level.

\subsubsection{UC10 --- Answer an Agent's Pending Question}

\textbf{Z coverage:} Same as UC9 --- modeled via \texttt{ReceiveMessage}
followed by \texttt{ReadMessages}.

\textbf{What the model proves:} The receive-then-read sequence is
always possible: \texttt{ReceiveMessage} increments the count, and
\texttt{ReadMessages} clears it. No deadlock between these operations.

\textbf{Gap:} None for V1.

\subsubsection{UC12 --- Coordinate File Ownership in a Shared Repo}

\textbf{Z coverage:} Partially modeled. The \texttt{SessionStart}
operation can inject coordination guidance (the \texttt{hasWall?} input
models context injection). \texttt{SetPlanManual} models the plan update
after negotiation.

\textbf{What the model proves:} The plan-before-work gate ensures that
both agents must declare their plans before editing files. If both agents
set plans, the plans are visible via \texttt{/who} (UC1), enabling
overlap detection. The model proves that \emph{no editing can begin
without a declared plan}, which is the foundation of file ownership
coordination.

\textbf{Gap:} The model does not enforce non-overlapping plans. Two
agents can both set plans and both edit files --- the model proves each
individually followed the protocol, not that the protocol prevented
conflicts. This matches the use case document's statement: ``biff is
coordination infrastructure, not a distributed lock.''

% ------------------------------------------------------------
\subsection{Group C: Broadcast}
% ------------------------------------------------------------

\subsubsection{UC6 --- Broadcast a Time-Sensitive Announcement}

\textbf{Z coverage:} Fully modeled.

\begin{itemize}
  \item \texttt{PostWall} --- sets \texttt{wallActive = ztrue},
    \texttt{wallText = \{text?\}}.
  \item \texttt{ClearWall} --- sets \texttt{wallActive = zfalse},
    \texttt{wallText = $\emptyset$}.
  \item \texttt{StartSession} --- loads wall state at session start
    via \texttt{hasWall?} and \texttt{wallContent?} inputs.
\end{itemize}

\textbf{What the model proves:}

\begin{enumerate}
  \item \textbf{Wall consistency}: \texttt{wallText} exists iff
    \texttt{wallActive = ztrue}. No ghost text, no active wall without
    content (invariant 3).
  \item \textbf{Wall visibility at startup}: \texttt{StartSession}
    propagates the wall into session state. A new session joining after
    a wall post will have \texttt{wallActive = ztrue} if a wall exists.
  \item \textbf{ClearWall requires active wall}: precondition
    \texttt{wallActive = ztrue} prevents clearing a non-existent wall.
\end{enumerate}

\textbf{Gap:} Wall TTL (expiry) is not modeled. The wall persists until
explicitly cleared. Adding TTL would require a time dimension
(monotonic clock), which significantly increases model complexity.

\subsubsection{UC15 --- Notify Team of CI/CD Status}

\textbf{Z coverage:} Modeled via \texttt{PostWall} (for \texttt{/wall})
and \texttt{ReceiveMessage} (for \texttt{/write} from GitHub to
committer).

\textbf{What the model proves:} The GitHub actor uses the same
operations as any other actor. The model does not distinguish actor
types (matching the use case document: ``The system does not distinguish
actor types at the protocol level''). All invariants hold regardless of
who triggers the operation.

\textbf{Gap:} GitHub's service token authentication is outside the
model (T2 configuration). The model assumes the actor is already
authenticated and has a valid session.

% ------------------------------------------------------------
\subsection{Group D: Real-Time Conversation}
% ------------------------------------------------------------

\subsubsection{UC14 --- Have a Synchronous Exchange}

\textbf{Z coverage:} Fully modeled.

\begin{itemize}
  \item \texttt{StartTalk} --- sets \texttt{talkActive = ztrue},
    guarded by \texttt{talkActive = zfalse} (no double-start).
  \item \texttt{EndTalk} --- sets \texttt{talkActive = zfalse},
    guarded by \texttt{talkActive = ztrue} (no double-end).
\end{itemize}

\textbf{What the model proves:}

\begin{enumerate}
  \item \textbf{Talk exclusivity}: exactly one talk session at a time.
    No path through the model allows \texttt{StartTalk} to fire twice
    without an intervening \texttt{EndTalk}.
  \item \textbf{Talk survives tool calls}: \texttt{talkActive} is
    preserved through the \texttt{BiffFrame} abbreviation. Tool calls,
    subagent spawns, and response cycles do not accidentally clear the
    talk state.
  \item \textbf{Clean shutdown}: \texttt{EndSession} clears
    \texttt{talkActive}, so no orphan talk sessions persist after logout.
\end{enumerate}

\textbf{Gap:} The model does not capture individual talk messages or
\texttt{/talk\_listen} blocking behavior. Talk messages are modeled the
same as \texttt{ReceiveMessage}. The blocking semantics of
\texttt{talk\_listen} (agent waits for message) would require a new tool
phase state, which adds complexity without clear workflow invariant value.

\subsection{Group E: Focus Management}
% ------------------------------------------------------------

\subsubsection{UC13 --- Enter Do-Not-Disturb Mode}

\textbf{Z coverage:} Not modeled. The \texttt{mesgMode} variable was
proposed in the Layer 2 design but not included in the current spec to
keep the state space manageable.

\textbf{What the model proves:} Nothing specific to DND. However, the
\texttt{ReceiveMessage} operation fires regardless of DND state (matching
the use case: ``Messages sent to this actor still queue''). DND only
affects push notification suppression, which is a display concern outside
the state machine.

\textbf{Proposed extension (if needed):}

\begin{verbatim}
  mesgMode : ZBOOL  % ztrue = accepting, zfalse = DND
  ...
  % Invariant: walls bypass DND (already modeled ---
  % wallActive is independent of mesgMode)
\end{verbatim}

\textbf{Recommendation:} Do not add unless a workflow invariant depends
on DND state. Currently no use case requires ``the agent must be in
DND before doing X.''

% ------------------------------------------------------------
\subsection{Group F: Agent-to-Agent Coordination}
% ------------------------------------------------------------

\subsubsection{UC11 --- Avoid Duplicate Work Across Agents}

\textbf{Z coverage:} Partially modeled. The plan-before-work gate
ensures every agent declares work before editing. The
\texttt{StartSession} operation's wall injection models the SessionStart
hook's coordination guidance.

\textbf{What the model proves:} Every actively editing identity $a$ has
\texttt{planSet(a) = ztrue}. This means \texttt{/who} output will always
show a plan for every working agent --- and, since biff-ar1/om9
(\S\ref{sec:om9}), one concurrent agent's \texttt{SessionStart} can no
longer silently blank another's declared plan out from under it, which
is precisely the failure mode that made the earlier flat-boolean model's
duplicate-avoidance guarantee unsound for exactly this use case: two
agents sharing a worktree. The plan-before-work invariant is the formal
foundation for duplicate avoidance: if every agent must declare intent
before acting, the declarations are observable, persist independently,
and conflicts are detectable.

\textbf{Gap:} The model does not verify that the agent actually checks
\texttt{/who} before starting work. This is a behavioral directive
(injected via SessionStart hook), not a state machine constraint. To
formalize it, you would need a \texttt{whoChecked : ZBOOL} variable
set by a \texttt{/who} query and required as a precondition on
\texttt{SetPlanManual}. This is feasible but may be over-constraining ---
the agent might legitimately set a plan without checking \texttt{/who}
if it knows no other agents are active.
